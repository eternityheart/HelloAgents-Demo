## 📖 Part 1: 概念理解

### 什么是 POI？
**POI** = **P**oint **O**f **I**nterest (兴趣点)
它是地图上的一个个"点"，比如：
- 故宫 (景点)
- 全聚德 (餐厅)
- 北京饭店 (酒店)
- 加油站 (服务设施)

### 为什么不用关键词搜索此？
虽然 API 支持关键词搜索（如"故宫"），但更强大的是**分类搜索**。
通过类型代码（如 `110000` 代表景点），我们可以查出"北京所有的景点"，不论它名字里有没有"景点"两个字。

### 🔑 高德 POI 类型代码表

| 类型 | 代码 | 例子 |
|------|------|------|
| 景点 | 110000 | 故宫、长城、公园 |
| 餐厅 | 050000 | 肯德基、全聚德 |
| 酒店 | 100000 | 如家、希尔顿 |
| 购物 | 060000 | 商场、超市 |
| 交通 | 150000 | 地铁站、停车场 |

## 🔧 Part 2: 实战代码

### 核心代码结构 (`src/phase2/amap_poi_test.py`)

```python
# 1. 基础配置
POI_SEARCH_URL = "https://restapi.amap.com/v3/place/text"
POI_TYPES = {"景点": "110000", "餐厅": "050000"}

# 2. 搜索参数
params = {
    "key": AMAP_API_KEY,
    "city": "北京",
    "citylimit": "true",  # 限制在城市内
    "keywords": "故宫",   # 关键词 (可选)
    "types": "110000",    # 类型代码 (可选)
    "offset": 5           # 返回几条
}

# 3. 发送请求
requests.get(url, params=params)
```

### 关键参数解析
- **citylimit=true**: 非常重要！如果不加，搜"北京大学"可能会搜到全国各地的分校。
- **types**: 使用官方代码比关键词更准。
- **offset**: 控制返回数量，避免 LLM 处理太多内容爆 Token。

## 🎓 面试话术

### Q: 你的 Agent 如何获取地点信息？
> "我集成了高德地图的 POI 搜索 API。相比简单的关键词匹配，我更倾向于使用**结构化查询**（如指定 city 和 types），这样能大幅提高搜索结果的准确性。例如，当用户说'找个地吃饭'时，我会映射到类型代码 `050000` (餐饮服务)。"

### Q: 如何处理 API 返回的大量数据？
> "由于 LLM 的 Context Window 有限，我会在 API 请求时使用 `offset` 参数限制返回数量（通常 5-10 条）。同时，在 Worker 内部会做数据清洗，只提取 name、address、rating 等关键字段返回给 LLM，过滤掉冗余的 JSON 结构。"
