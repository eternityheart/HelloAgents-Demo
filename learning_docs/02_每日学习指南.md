## Day 1: 环境搭建 🏗️

### 今日目标
- [ ] 安装Python 3.11+
- [ ] 创建虚拟环境
- [ ] 配置API密钥
- [ ] 验证环境正确

### 🧒 小学生讲解
> 想象你要开一家"智能旅行社"，今天的任务是：租办公室、装电脑、办营业执照。
> 对应到编程就是：装Python、建环境、申请API密钥。

### 📝 操作步骤

#### Step 1: 安装Python
1. 访问 [python.org](https://www.python.org/downloads/)
2. 下载 Python 3.11.x（推荐3.11.9）
3. 安装时勾选 "Add Python to PATH"
4. 验证：打开终端输入
```bash
python --version
# 应显示: Python 3.11.x
```

#### Step 2: 创建项目环境
```bash
# 进入项目目录
cd e:\antiPro\agentdemo1

# 创建虚拟环境
python -m venv venv

# 激活环境 (Windows)
venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt
```

#### Step 3: 配置API密钥
```bash
# 复制配置模板
copy .env.example .env

# 编辑.env，填入你的密钥
# DEEPSEEK_API_KEY=sk-xxxxx
# AMAP_API_KEY=xxxxx
```

#### Step 4: 验证环境
```bash
python src/config.py
# 应显示配置状态
```

### ❌ 常见错误与解决

| 错误 | 原因 | 解决方案 |
|-----|------|---------|
| `python不是命令` | PATH未配置 | 重新安装，勾选Add to PATH |
| `pip install超时` | 网络问题 | 使用清华源：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt` |
| `.env not found` | 文件未创建 | 确认复制了.env.example |

### ✅ 今日自测
1. [ ] `python --version` 显示3.11.x
2. [ ] 虚拟环境能激活（提示符前有`(venv)`）
3. [ ] `python src/config.py` 不报错

### 🎓 面试笔记
> **Q: 为什么要用虚拟环境？**
> A: 隔离项目依赖，避免不同项目的包版本冲突。这是Python项目的工程化最佳实践。

### 今日目标

### 🧒 小学生讲解
> 昨天的员工只会"说话"，今天教他"用工具"！
> 就像给员工发一个工具清单：
> - 用户问天气？→ 用"天气工具"
> - 用户问景点？→ 用"搜索工具"
> 员工看到问题，会自己决定用哪个工具！

### 📝 动手实验

#### 实验1: 运行Function Calling示例
```bash
python src/phase1_function_calling.py
```

观察控制台输出，注意：
- 什么时候调用了工具
- 什么时候没调用
- 调用了什么参数

#### 实验2: 添加新工具
在代码中添加一个新工具：`get_exchange_rate`（查汇率）

```python
# 1. 添加工具函数
def get_exchange_rate(currency: str) -> dict:
    """获取汇率"""
    rates = {"USD": 7.2, "EUR": 7.8, "JPY": 0.048}
    return {"currency": currency, "rate": rates.get(currency, 0)}

# 2. 添加工具定义
# (参考 phase1_function_calling.py 的 TOOLS_DEFINITION 添加)

# 3. 添加函数映射
# TOOL_FUNCTIONS["get_exchange_rate"] = get_exchange_rate
```

测试："100美元能换多少人民币？"

### 核心概念图
```
用户: "北京天气怎么样?"
         ↓
    [LLM分析意图]
         ↓
    "我需要调用get_weather工具"
         ↓
    [执行 get_weather("北京")]
         ↓
    {"weather": "晴天", "temp": 25}
         ↓
    [LLM组织回答]
         ↓
    "北京今天天气不错，晴天25度"
```

### ✅ 今日自测
1. [ ] 问天气时能看到工具调用日志
2. [ ] 闲聊时不会调用工具
3. [ ] 成功添加了新工具并测试通过

### 🎓 面试笔记
> **Q: Function Calling的原理是什么？**
> A: 工具定义通过JSON Schema注入system prompt，LLM输出结构化的函数调用请求。我们执行函数后，把结果反馈给LLM，让它生成最终回答。这是ReAct（Reasoning + Acting）模式的基础。

### 🎓 面试笔记
> **Q: 为什么不用一个Agent做所有事？**
> A: 单一Agent提示词会过长，职责不清。拆分后：
> 1. 每个Agent提示词更精确
> 2. 可以并行执行提升效率
> 3. 方便独立测试和维护
> 4. 符合单一职责原则
